## Stop: the ladder's source is not listed

The brief allows downloads only from URLs or hosts listed in `sources.yaml`, `golden.yaml` or
`refdb.yaml`, in the form the ladder used, and says to stop if the ladder's source is not listed
(AGENTS.md §8 is stricter: URLs listed, not hosts).

- `sources.yaml` does not exist at the repository root, on any branch (`git log --all -- sources.yaml`
  is empty) or in `~/bio-box` on the pod. The only file of that name is `tests/fixtures/micro_s0/sources.yaml`.
- The ladder fetched all 2,497 genomes from the NCBI Datasets v2 REST API,
  `https://api.ncbi.nlm.nih.gov/datasets/v2/genome/accession/<A1>,...,<A20>/download?include_annotation_type=GENOME_FASTA`
  (`fetch_result.json` of P1 and P2 on the pod: `fallback_single` 0, `fallback_ftp` 0). The host
  `api.ncbi.nlm.nih.gov` appears in none of the three files.
- Its fallback, the genomes FTP over HTTPS (`https://ftp.ncbi.nlm.nih.gov/genomes/all/...`), is on a
  host that `refdb.yaml` lists (for `hmm_PGAP.HMM.tgz`), but the URL is not listed, and the ladder
  never actually used it.
- `golden.yaml` lists `eutils.ncbi.nlm.nih.gov/.../efetch.fcgi?db=nuccore` by nucleotide accession.
  That is not the ladder's form, takes no assembly accession and ships no checksum.

To unblock: add a source entry for the Datasets v2 genome download (and, if wanted, the
genomes/all FTP fallback) to `sources.yaml`. That is a PI or H-card change. Then run the launch
command below.

## Fetch (ready, not started)

`scripts/stress/build_stage_pod/r50_fetch.py` (pod copy `/tmp/if2453/r50/bin/r50_fetch.py`) is the
ladder's `fetch.py` with the same source, tool and pace: Python `urllib`, Datasets v2 batches of
20, one connection, at most 3 requests per second, user agent `ladder-fetch/1.0 (python-urllib)`, no
key or email; a missing accession is retried alone, then through the genomes FTP. Additions:

- Each FASTA is checked against the source's md5: `md5sum.txt` in the Datasets zip (md5 of the
  `.fna`), or `md5checksums.txt` in the FTP directory (md5 of the `.fna.gz`). A mismatch is
  fetched once more alone, then listed as failed. Its own sha256 is recorded in `lock.json`.
- The log has one line per genome: `/tmp/if2453/r50/fetch.log`.
- The data root's `STOP` file is checked before each batch. Five refusals in a row (HTTP 403, 429 or 503)
  stop the run.
- At the end the script writes `/tmp/if2453/r50/DONE` (every genome verified or listed as failed) or
  `/tmp/if2453/r50/FAILED` (stopped early, with the reason).
- It is resumable: a genome in a stage's `lock.json` whose file has the recorded size is skipped.

Offline test: `r50_fetch.py selftest /tmp/if2453/ladder/dl_test/t.zip /tmp/if2453/r50/selftest`
(the ladder's two-genome test zip, already on the pod; no network) extracted both FASTAs and
matched `md5sum.txt`. The system `md5sum` gives the same digests (`1fd428ef…`, `92c997bc…`).

Layout, the ladder's: `/tmp/if2453/r50/genomes/<stage>/<accession>.fna` with `lock.json` and
`fetch_result.json` per stage, on local disk (`/`, 806 G free at 00:56 CST).

Launch or resume (on the pod; the launcher refuses if `r50-fetch` is active, `STOP` is present,
or `/tmp` has less than 240 GiB free):

```
sh /tmp/if2453/r50/bin/r50_fetch.sh
```

This runs `systemd-run --user --unit=r50-fetch --collect -p MemoryMax=8G -p MemorySwapMax=0
-p CPUQuota=200% nice -n 19 python3 -I /tmp/if2453/r50/bin/r50_fetch.py /tmp/if2453/r50/selection
/tmp/if2453/r50/genomes /tmp/if2453/r50/fetch.log --stages P3,P4,P5,P6`.

Expected size and time, both *derived* from the ladder's P2 fetch (`fetch_result.json`: 2,250
genomes in 524.9 s, 2,782,879,419 bytes downloaded, 9,716,599,273 bytes written for
9,596,180,328 bp):

- Stored size: 40.4 GB of `.fna` (39,886,137,556 bp × 1.01255 bytes per bp). `/` would keep about
  765 GB free.
- Download: 11.6 GB (39.9 Gbp × 0.2900 downloaded bytes per bp).
- Time: about 37 min at the ladder's 257 genomes per min and 5.3 MB/s. This is an *estimate*:
  the ladder's rate was one night's.
