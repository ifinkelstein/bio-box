## Runbook errors and unclear places (kept as found)

1. RUNBOOK §2 says a finished build logs `all 13 steps done`. Without `--library` it is
   `all 12 steps done` (`r10-S1-1`): the count is the length of the step list, one more per library.
   §2 also never says that `--library` may be left out; the code allows it (`Build.libraries = ()`).
2. RUNBOOK §2: "For a real Pfam scan by day, with the real profile: `--scan-jobs 10 --scan-cpus 4`."
   That is 40 threads, the account's whole day cap, while the cap is a total across every agent of
   the account (three other agents' test suites run beside a build). The runbook does not say that
   `--scan-jobs` × `--scan-cpus` plus everything else the account runs must stay under the cap.
3. RUNBOOK §2 ("A shard that fails stops new launches. Shards already running finish and publish")
   and §3 (a step running when `STOP` appears "finishes its command. `run-step` then publishes
   nothing") together mean: after `STOP`, every shard that ends while `STOP` is still present is
   discarded, not published. §3's "During a scan in shards it checks before each shard launch,
   launches no more, and waits for the shards that run" reads as if the running shards were kept.
   Removing `STOP` as soon as `build-stage` logs `launching no more shards` keeps all but the first
   (what `r10_phase2.sh` does).
4. RUNBOOK §0 `bio-box()`/`biopy()` put `python -c '...'` one-liners inside nested quotes; run through
   `ssh '...'` and `bash -c "..."` they need a third quoting level, and the first attempt here
   (`r10-check-S1`) failed with `unexpected EOF while looking for matching '"'`. A script file
   (`r10_verify.py`) avoids it.
