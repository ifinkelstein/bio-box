# Copy measured Pfam rows instead of scanning again: the plan of stage H1 (card B-47b)

Date: 2026-11-15, wilkcomp02 (the pod's clock, CST). Every number carries a label: *measured* (host, date, command or
file), *derived* (formula and inputs) or *estimate*. Read-only on the data root `/tmp/if2453/r10/root`: the plan ran in
a scratch view of symlinks (`/tmp/if2453/b47b/view`) and wrote only there; no scan was run; nothing under `/stor` was
written (the Pfam file was bound read-only). A `STOP` file in the data root was checked before each step.

## Summary

- **Design** (`src/biobox/l1/domains.py`, module docstring; DEC-35 (2), design note §2b). `domains.plan` given
  `seq_stages` that name another stage leaves out every protein a source stage measured with the same scan and records
  it for the merge to copy; `domains.merge` copies those proteins' rows between the shards' rows, in uid order, so the
  stage's `l1_domains` files and ledger are a full scan's, byte for byte. build-stage gives the plan step the root's
  other stages as `--seq-stages`, and runs a scan in shards whenever a source exists, since only a plan records what is
  copied (`stage.py`, module docstring). The scanned and copied counts are in the plan (and the scanned ones in the
  shard records): never in a manifest, not in the ledger.
- **What "measured" means** (orchestrator's addition 1): decided from the source's records, never from its rows. A
  stage is a source only when its `domains-<lib>` step is complete (its run record `runs/stage=<S>/domains-<lib>.json`,
  no `.publishing.json` beside it, listing its domain files and its ledger with sha256) and it has a shard plan, whose
  `files` are the `protein_seq` files it measured. A stage scanned in one process has no plan, records no sha256 of its
  HMM file, and is not a source (its proteins are scanned again). A protein scanned with no hit is measured: it is
  copied as no rows.
- **Fields compared** (addition 2; `domains.COMPARED`): the source plan's `hmm_sha256` and `cutoff`; its `z` and
  `dom_z` (plans written before this card hold neither and are taken at 1e8: `Z_PROT` and `DOM_Z` have been 1e8 since
  `74b3e05`, the commit that wrote the module, `git log -G '^(Z_PROT|DOM_Z) ='`, and the merge checks every row it
  writes has this scan's `cutoff`, `z` and `dom_z`); and the `tool_versions_json` of every row of the source's ledger
  (pyhmmer and pyarrow), against the planning process's `provenance.tool_versions`. The merge refuses to run under
  other tool versions than the plan's. A named stage that does not qualify is listed in the plan's `copy.passed_over`
  with the reason.
- **Shards and estimate** (addition 3): the shards are cut from the residues left to scan; build-stage says, after the
  plan step, the copied proteins and the estimate from the scanned residues.
- **No other stage, or nothing shared** (addition 4): the plan, shards and merge of card B-24, byte for byte (a plan
  naming only the stage itself is today's plan byte for byte; test). The fixture's manifest hash is unchanged:
  `28ffa9808ecd4829e52f6892f94f7b85` (*measured*, wilkcomp02, 2026-11-15, `tests/r3/test_cross_host.py` with
  `BIOBOX_PEER_MANIFEST` holding the integration branch's hash: both tests pass).
- **Bounded memory** (addition 5): the proteins are matched by a merge of sorted uid streams (`domains._assign`), the
  stage's and each source's, one row group (or one 16,384-row batch) at a time; never a set. Memory test below.
- **Several sources** (addition 6): the first in the order given; the files are the same in either order (test).
- **Inferred rows** (addition 7): two places for card B-47c, named in the module docstring: `_measured_uids` (the
  proteins a source measured) and `_measured_rows` (the rows read from a source's domain files).

## The acceptance measurement: the plan of H1 naming S1 and P1 to P6

Inputs: the data root's `protein_seq` of H1, S1, P1 to P6 and the Pfam 38.2 scans of S1 and P1 to P6 (their domain
files, plans, ledgers and run records), linked into the view; H1's own scan is not linked (a plan refuses a stage whose
domain files exist). All seven sources have format-1 plans with the same `hmm_sha256` (`2d82087b6c5c60d7…`), cutoff
`gathering`, and ledgers recording pyhmmer 0.12.3 and pyarrow 26.0.0 (*measured*, the files). The command, in the
runtime image of `faec1f4` (RUNBOOK §0, `bio-box_faec1f4.sif`) with this branch's `src`, one thread, in scope
`b47b-plan` (`MemoryMax=8G`, nice 19), timed by a wrapper (`timed.py`, appendix):

```
python -m biobox.cli stage domains plan --root /tmp/if2453/b47b/view --stage H1 --library pfam --library-version 38.2 \
  --hmm /stor/scratch/Wilke/if2453/all-the-data/l0/refdb/pfam/38.2/Pfam-A.hmm.gz --cutoff gathering \
  --shard-residues 30150753 --seq-stages H1,S1,P1,P2,P3,P4,P5,P6
```

## Memory test (AGENTS §4.2)

`tests/r2/test_b47b_copy_memory.py`: the synthetic store of `scripts/stress/synth_scale.py` at 10 and 100 copies, a
stage T holding the same proteins as S0, S0 a completed source; T's plan and merge copy every protein (no shard) in a
process of its own, and T's domain file equals S0's byte for byte. Peak RSS (*measured*, wilkcomp02, 2026-11-15,
`runstep.step_peak`): 155.5 MiB at 10 copies (8,540 proteins, 6,890 rows), 203.3 MiB at 100 copies (85,400 proteins,
68,900 rows), growth 47.8 MiB. Bounds stated in the test: growth at most 64 MiB, peak at most 512 MiB. At 100 copies
each table is still about one row group, so the growth is one row group's worth of rows and uid lists, not a growth
with the stage. The first version of the merge held one table slice per copied protein until a row group filled: 202.6
and 748.2 MiB, a growth of 545.6 MiB (*measured*, same test); the merge now combines its slices every 1,024 pieces
(`domains.FLUSH_PIECES`).

## Appendix: the scripts (in `/tmp/if2453/b47b/bin` on the pod)

`view.py SRC DST` makes DST with real directories and one symlink each to: `l0seq/protein_seq/<gcv>/stage=<S>` for H1
and the seven sources; for each source `l1/domains/library=pfam-38.2/stage=<S>`, `l1/domain_scan/library=pfam-38.2/
stage=<S>`, `ledger/stage=<S>/step=domains-pfam-38.2` and `runs/stage=<S>/domains-pfam-38.2.json` (36 links). It
refuses an existing DST (the pattern of `scripts/stress/build_stage_pod/c33_view.py`).

`timed.py OUT -- CMD` runs CMD and records its wall time, and the CPU time and peak RSS of its process tree
(`RUSAGE_CHILDREN`).

`compare.py VIEW ROOT OUT TMP`: (1) in DuckDB (6 GB, 4 threads), H1's `protein_seq` rows joined with the union of the
sources' (each source's files from its own plan in the root), the first source per protein in the order S1, P1 to P6;
(2) `domains._walk` over the plan's sources gives the rows to copy for each copied protein; H1's own rows are read from
the root's H1 domain file filtered to the copied uids; the two are compared as lists of rows per protein.
