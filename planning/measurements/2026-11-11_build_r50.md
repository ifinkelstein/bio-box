Cause (`r50_dup.py`, `r50_shared.py`, read-only): the contig `ee816c57…` (6,963 bp) is stored by stage **P1**
(`l0seq/contig_index/stage=P1/part-0.parquet`). It is the plasmid CP144829.1 of *Candidatus* Stammera capleta isolate
GJDJECCL (GCA_036689455.1, P3), byte for byte the plasmid CP144826.1 of isolate NMKNNIEB (GCA_036689445.1, P1);
GTDB places the two isolates in different species, so both were picked. Ingest correctly stores the sequence once
(in P1) and gives P3 no new row for it, but gene calling of P3 reads only P3's sequences. `genecall` has the option
for exactly this case, `--seq-stages` (card B-28: "the stage itself and, when its contigs repeat sequences stored
before it, the earlier stages that hold them"), but `build-stage` never passes it (`steps` in `src/biobox/stage.py`
builds `stage genecall --tmp ... --workers N` only). Whether `igr` and `tapes` would then also need the earlier
stage was not tried.

Every new stage has such a contig (`r50_shared.py /tmp/if2453/r10/root P3=... P4=... P5=... P6=...`, contig uids of
the input lists against the root's `contig_index` and the earlier lists; output `/tmp/if2453/r50/logs/shared_contigs.json`):

| Stage | Contigs named | Stored by an earlier stage | Where |
|---|---|---|---|
| P3 | 9,108 | 1 | P1 (`ee816c57…`) |
| P4 | 4,006 | 1 | P2 (`6d0c6d93…`) |
| P5 | 4,112 | 1 | S1 (`2c578408…`) |
| P6 | 4,228 | 1 | S1 (`17aa83e5…`) |

So `build-stage` as it is cannot build any of the four stages. Making it pass `--seq-stages` (the stage and the
release's stages before it, or the stages that store its shared contigs) is a code change for a card; running gene
calling by hand with `--seq-stages` would be improvising around the failure, which the brief rules out. Left in the
root by P3, all new files of a new stage (AGENTS §3.10 allows them): `runs/stage=P3/{inputs,ingest}.json` and their
outputs (`genome_input`, the ingest's 36 files). The next `build-stage` of P3 skips both and resumes at gene calling.
`/tmp/if2453/r50/tmp/staging/P3.genecall` (4 K) is left for `run-step` to remove at that next start (RUNBOOK §4).
