# S2C ANI diversity: does GTDB R226 publish the values? (card C-25, step 1b; 2026-11-12)

Step (1b) of card C-25 only (DEC-31). No genome and no GTDB data file was fetched, and nothing was built. Numbers are
labelled *measured* (host, date, command), *derived* (formula and inputs) or *estimate*. Times are CST.

## Result in one paragraph

**GTDB R226 publishes no ANI value between two genomes.** The release's whole file tree (its `MD5SUM.txt`, 67
files) holds one file with ANI in it, `auxillary_files/sp_clusters_r226.tsv` (38,621,586 bytes), and it has one row
per species cluster: the representative, the member list and the ANI radius used to draw the cluster. The genome
metadata has no ANI column (step 1, *measured*). GTDB-Tk's reference package (141,442,235,198 bytes) covers the
143,614 representatives only. The GTDB web API computes skani on request and stores nothing. So GTDB does not
publish what DEC-31 needs, a value for every pair among the 28,726 complete genomes of the 243 species with more than
20. It does not publish genome-to-representative ANI either, so the cheaper middle path does not exist from GTDB
files. **Per the card, I stopped here.** Nothing was added to `sources.yaml` and nothing was fetched. A skani step
would have to download **28,483 genomes, 118.8 Gbp** (the 243 rank-1 genomes are already in phase 1). That is about
34.5 GB compressed and 120.3 GB of `.fna` (*derived*). It is **23,866 genomes and 101.6 Gbp more** than the
quality-only phase 2 fetches in those species. The compute is small next to that download: a greedy farthest-first
pick needs 499,624 genome pairs (all pairs: 15,835,149), roughly 4 to 17 CPU-hours for skani (*estimate*, basis
below).

## Part B: the decision

**Not enough, so I stopped (card C-25 1b; DEC-31).** The test was whether some file gives an ANI or a distance for
every pair among the 28,726 complete genomes of the 243 species. None does. No file gives a structure from which an
unbiased diversity order could be made either. So:

- `sources.yaml` was **not** changed: DEC-31 adds a GTDB ANI source only if it covers every pair.
- Nothing was fetched, and `/tmp/if2453/c25/ani/` was not created.
- `c25_select.py` gained no `--ani` option.

**Genome-to-representative ANI, if it existed.** R226 does not publish it (above). Had it been published, it would
give each genome one number, its distance from one point. Spreading the 20 picks over that range keeps a genome near
the representative and one far from it apart. It cannot separate two genomes at the same distance from the
representative, which may be identical to each other or as far apart as twice that distance. It is a
one-dimensional proxy, not a diversity choice. In 86 of the 243 species the representative is not even a complete
genome (157 of 243 are complete, *measured* below), so the point would be a genome outside the candidate set.

**skani compute (*estimate*).** This is not measured, and the per-unit costs below are assumptions, not sourced
figures. skani is not in the image, and I did not run it.

- Assumed sketching cost: 0.5 to 2 CPU-s per genome of the mean size, 4.17 Mbp (*derived*: 119,700,310,300 /
  28,726). For 28,726 genomes that is 4.0 to 16.0 CPU-hours.
- Assumed cost per pair once sketched: 1 to 10 ms. Every pair in a species is above skani's screen, so all are
  computed. That gives 0.14 to 1.4 CPU-hours for the 499,624 farthest-first pairs, or 4.4 to 44 CPU-hours for all
  15,835,149 pairs (*E. coli*'s triangle alone up to 22 CPU-hours, beyond the 300-CPU-minute process rule unless
  split).
- Total for farthest-first: about 4 to 17 CPU-hours. It should be measured on one species (for example *S. aureus*,
  1,475 genomes) before anyone plans on it.
- Adding skani means changing `container/environment.yml` and rebuilding the image (an `AGENTS.md` §2 file, so a
  card of its own). I did not add it.

## Other routes (named for the PI, none adopted)

- **GTDB's skani service** (`gtdb-api.ecogenomic.org/skani/job`). Farthest-first is 19 sequential rounds per
  species, so the 499,624 pairs would be 4,617 small jobs (*derived*: 19 × 243). All pairs would be 15,835,149,
  at least 64 jobs at its 250,000-pair limit (*derived*). The service is not in `sources.yaml` (§8), it is not a published value (DEC-31), and it
  is a shared academic service never asked to take batch work of this size. It runs skani 0.3.0; GTDB's clustering
  used 0.2.1. Whether it accepts GTDB accessions server-side was not tested (`/skani/validate/genomes` suggests so).
- **Marker-gene distances** from `bac120_marker_genes_all_r226.tar.gz` (10,009,510,492 bytes). It covers every
  GTDB genome, so a distance could be computed for every pair without downloading a genome. But it is
  nucleotide identity over about 120 core genes, not whole-genome ANI. It saturates for near-identical isolates,
  which are the case the rule exists for, and it needs a method that has not been designed or tested. Not evaluated.
- **Metadata proxies** (step 1): distinct `ncbi_bioproject` / `ncbi_biosample`, spread over `gc_percentage`,
  `genome_size`, `ncbi_country`, `ncbi_date`. They cost nothing, but they are not ANI. They could replace the
  accession tie-break at the cut, which decides 485 genomes (step 1).

## Test

`tests/r1/test_c25_select.py::test_ani_needs_counts_match_brute_force` (covers D-01, D-04; ring R1) runs
`c25_ani_needs.py` with `--cap 3` on the step-1 test's hand-made rows plus 300 seeded random rows, in file order and
shuffled. It checks:

- the two outputs are equal;
- genomes, bp, rank-1 and ranks 2 to cap, against the pairwise `_beats` oracle;
- all pairs, by enumerating `itertools.combinations`;
- the farthest-first pairs, by simulating the pick;
- the complete-representative count.

It failed first because the script was absent (`CalledProcessError ... returned non-zero exit status 2`;
`1 failed, 3 passed`). With the script: `sh scripts/pod_pytest.sh C-25 tests/r1/test_c25_select.py tests/r0` gave
`199 passed in 5.91s` (wilkcomp02, in the image).
